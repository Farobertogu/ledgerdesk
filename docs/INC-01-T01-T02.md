## What changed

- Neutral root; the retained shell lives only in explicit legacy layouts and the legacy home.
  No legacy page or URL was moved. `/material` is a preparation surface, not the T03 viewer.
- Shared `reading/1` contract in `src/contracts/material_reading.ts`, runtime validators and a
  separate tolerant Problem Details consumer. Product contract imports nothing. The unchanged
  `t02-lectura/1` source schema and examples remain pinned evidence; the
  [canonical mapping](../tests/contracts/reading_profile_mapping.mjs) checks profile equivalence
  without translating source text or opaque IDs. It is not a production compatibility adapter.
- Server context/configuration and internal evidence/reading port declarations. The delivery
  interface keeps the controlled transport callback inside admission; these are obligations for
  T04, not an implemented authorization, evidence store or physical terminal.
- Real HTTP preparation routes: invalid form 400; no internal context 403; configured trial but
  no T04 implementation 503. Never old material, a fabricated empty success or demo fallback.
  Public requests use `/api/v1/material` and `/api/v1/material/{unit_id}/versions/{version_id}`.
  The historical translated detail route has no compatibility alias.
- Narrow syntax proxy before Next's dynamic decoding: malformed escapes otherwise returned 500.
- Owned local launcher validates before starting Next; Next's own Ready line is not an oracle
  for application initialization. Server checks remain; public inputs cannot configure the trial.
- Boundary checker uses the existing TypeScript parser and runs in the new `reading` CI job
  after installation. It rejects legacy algorithms and widgets in both directions, including
  orphan modules. Existing checks remain intact. The launcher's `@next/env` is now a direct
  dependency, reusing version 16.3.1 already resolved in the lockfile.
- PG16 Compose configuration prepared and syntax-validated, NOT provisioned. Local PostgreSQL17
  remains untouched. Source UI and all definition/architecture documents remain untouched.
- BOARD/README identify the active new-system work without deleting the legacy history.
  [ADR-029](../adr/ADR-029-isolated-reading-foundation.md) records the scoped technical choices,
  source equivalence and five retained SQL-reading pages that T04 must cover. The
  [public contract](reading-contract.md) documents the English API, projections and evidence limits.

Reproduce with `npm run test:reading`, `node ci/reading_boundary_check.mjs`, and
`node node_modules/typescript/bin/tsc --noEmit --incremental false -p tsconfig.app.json`.
For build/HTTP, set `LEDGERDESK_READING_TRIAL=0`, `LEDGERDESK_DEV_IDENTITY=0`,
`NEXT_TELEMETRY_DISABLED=1`; run `npm run build` then `npm run test:reading:http`.
The HTTP harness launches/stops its own loopback processes and substitutes a connection trap for DB.

passed `check`, `reading`, `db` and `app` for implementation commit `556eec2`.
Before merge, `reading` was added to the required GitHub Actions checks on `main`, preserving
`check`, `db`, `app`, strict checks and all other protection settings. Every subsequent PR head
must pass the required checks independently; this run is evidence for its named commit only.
