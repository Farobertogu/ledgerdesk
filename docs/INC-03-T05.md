## What changed

- `/access/intake` reuses the intake, workspace/detail, preparation and confirmation presentation with one request/controller owner. Views receive snapshots and callbacks and do not fetch or decide permissions.
- `intake-workspace/1` adds explicit context and preparation/effect/attempt/proposal queries under current server authority. Original reception and preparation representations remain separate. The [workspace contract](intake-workspace.md) names exact routes, admission and recovery behavior.
- Captured text becomes its exact UTF-8 original. Text/Markdown, positional CSV and bounded XLSX use existing real producers. Formula, observed stored value, blank/zero/error, component coverage, conditions and differences remain distinguishable. Human preparation is not relabelled extraction.
- Each sensitive response is bound to the exact session and local item/revision. Local drafts remain in memory; the per-tab journal stores bounded locators and intention fingerprints, not bodies or credentials. An uncertain effect is reconciled, not automatically retried.
- A stop retains the independent, currently authorized right to read the exact sealed original. The localized private-phase SQL change does not reopen upload, finalization or processing. Discard removes unsent local data only.
- Two mandatory workspace jobs are added to `reading`, preserving all seventeen baseline jobs. The resulting nineteen-job workflow is wired and locally checked; it has not run remotely for this uncommitted delivery.

The extraction worker, format adapters and existing editorial construction/effect algorithms are reused. There is no new extractor, approval path, corpus publication or legacy identity fallback.

## Reproduction

Use Node 22, installed pinned repository dependencies and the Linux Docker engine. No host certificate/hosts changes, historical databases, real documents, external mail or model calls are required. Run one owned runtime group at a time; the runner's claim and labeled resources prevent overlapping ownership. Original demo and documentary trial directories are not build inputs modified by these commands.

```sh
npm ci
node --experimental-strip-types ci/intake_ui_check.mjs --group units
node --test tests/intake/ui/views/test_views.mjs
node --test tests/intake/ui/test_ci.mjs tests/intake/t02/test_ci_wiring.mjs
node ci/intake_ci_check.mjs
```

Run the bounded browser groups individually by substituting one of `ui-first-slice`, `ui-reception`, `ui-preparation`, `ui-protection`, `ui-resources`, `ui-adoption-reception`, `ui-adoption-preparation` or `ui-disclosure-navigation`:

```sh
node --experimental-strip-types ci/intake_t02_check.mjs --group extraction --extraction-cases preparation --preparation-cases ui-first-slice
node ci/intake_workspace_guards.mjs
node --experimental-strip-types ci/intake_t02_check.mjs --group fence-sql
node --experimental-strip-types ci/intake_t02_check.mjs --group fence-restore
node --experimental-strip-types ci/intake_t02_check.mjs --group fence-coupled
```

The runner constructs and identifies the actual route and direct HTTPS terminal, uses real PostgreSQL/object/worker services, and removes only its exact owned resources. Each run has a unique directory; failed evidence is retained. `runtime/workspace-*.png` contains screenshots, `workspace-observations.json` contains directed observations, and bounded browser diagnostics contain no protected request bodies or credentials. These private observations are distinct from the closed public export.

The two new CI producers enforce the eight groups, local checks and directed mutation under separate 20-minute job ceilings. Their actual hosted duration and success remain unmeasured. A skipped, failed, missing or cancelled required producer fails the aggregate; no `continue-on-error` or automatic test retry was added.
