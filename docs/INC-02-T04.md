# INC-02 · T04 · Authenticated reading and scoped people

## Scope

Local synthetic implementation on `card/INC-02-authorized-reading`, based on
`a991f74` (the accepted T03 baseline). ADR-035 is proposed. This report records the
local implementation and validation; publication and remote CI are tracked in the
pull request. It does not establish merge approval or production acceptance.

The implemented journey is invitation-backed account → current HTTPS session →
capability inventory → authenticated material list/exact original. `/people`
provides a separately authorized, paginated nominal census. The full administration
interface and whole-increment acceptance remain T05/T06 work.

## Implementation

### Shared authority and projection

`src/server/access/invitation_authority.ts` remains the common evaluator for
invitations, capabilities and reading. The new adapter loads current session,
account, grants, support, declaration, surface and policy in one admitted Repeatable
Read snapshot. The ceiling restricts an existing material-policy grant; it cannot
create one. A grantor or master cannot read simply because that account can invite.

`src/server/reading/policy.ts` and `src/contracts/material_reading.ts` are unchanged.
`reading/1` keeps its exact body shape and original text. The internal context type
allows the new surface/purpose identifiers; the old trusted fixture constructor is
unchanged. No normalization, source translation or identity metadata enters the DTO.

`ci/access_material_schema.mjs` extracts the two table definitions from
`src/server/reading/postgres/001_trial.sql` and inserts them into the additive
`003_authorized_reading.sql` migration. The marker-bearing migration must be
rendered through `authorizedReadingMigration()`; do not apply its source directly.
The extraction rejects changed boundaries, extra tables, roles and functions.
The common definition is shared; each installation's role/control/lock context is not.

The new `inc02_reader` role selects the authority columns needed by the decision
and the material projection. It cannot select account email/verifier or session
CSRF, write grants/policy, impersonate owners or access legacy private data.
`inc02_runtime` cannot select the new material tables. Evidence is append-only;
the reader can append evidence/observations but cannot rewrite them.

### Admission, evidence and failure

Shared deployment admission is 20202; sorted effective object locks remain 20203.
The same connection retains admission after evidence commit through the terminal's
handoff. Control functions for material policy, surface readiness, treatment,
investiture ending and event revalidation use 20202, as do existing session,
support and grant invalidators. No 10404 control function is copied into INC-02.

The prior evidence row records actor/session references, surface, purpose, object,
generation, authority facts, planned status and time. A later row records handoff
or interruption. Neither a commit nor `res.end` proves human receipt. The browser
tests independently observe response arrival and the displayed original.

Missing session gives the unchanged reading 403. A current session with no
disclosable material receives the same reading 404 as an absent unit. Unavailable
surface policy, unreconciled control and evidence failure give 503. No current
content is emitted after a failed preparation/commit. Origin/parser rejections
occur before material evidence and do not gain a policy by reusing another route.

### People and cursor bounds

Nominal names are supplied by a synthetic `census_entry` with a source-act reference;
no email fallback, editable personal profile or public person-linking route is added.
The service reads bounded account/scope/revision selectors first, authorizes the
population, then orders and pages it. Only page-selected names are fetched.

Cursor state lives in `material_trial.census_cursor`. Public tokens contain 32 random
bytes; only a keyed digest is stored. Continuation is bound to the exact account
and session, the fixed synthetic deployment, generation, page configuration,
population/authority revision and expiry. Reauthorization happens on continuation.
Tampering, another account, another session of the same account, population change
and expiration are all neutral 404 cases. A cursor is not a bearer permission.

The census response's `revision` is an opaque numeric fingerprint, not a monotonic
counter. It projects the first 12 hexadecimal digits of the population/authority
digest into a positive integer. It has no ordering meaning and must never be used
as `expected_revision`; equal public values do not prove equal snapshots. Cursor
validation uses the full server-held digest and exact session binding, not this
truncated public value. See [the access contract](access-contract.md#wire-revision-and-result-rules).
The deployment/material control counter is not substituted: it is not a census-wide
counter covering every population and authority change.

Trusted configuration requires `inc02_reader` on loopback PostgreSQL 16,
`inc02_synthetic`, the declared port, a 16–128-character generation, a 1–300-second
cursor lifetime, 1–100 live cursors per session and 1–100 rows per page. The census
and authority snapshots each stop at 1,000 rows. The runtime example uses a one-row
page to exercise real continuation. These are trial bounds, not production choices.

### Declarations and restoration

Missing, ended, conflicting and declared-but-unaccredited functions have different
internal facts. Current declarations restrict purpose/grade. Event-based termination
requires a current satisfied event; an explicit scoped resolution is required for
conflicting grades/purposes. Fixture rows supply organizational determinations;
this does not accredit them or implement their public management.

The conditional independence predicate requires currently authorized, distinct
people. R19 loads actual database-backed person/account links, including two
accepted accounts belonging to one person. This is a predicate test, not an R3
workflow or completed multi-person approval.

After the material extension is installed, a trusted launcher must supply an
expected current generation independently of the stored snapshot. A missing or
mismatching generation closes the extended service even if the backup's flags say
ready. Material treatment flags close their dependent surfaces, not an otherwise
admitted identity session. This fixture establishes deny-until-reconciled behavior;
it is not a full backup restore exercise or a production reconciliation service.

### Interface and explicit transports

`/access/material` uses `session/1` with the validated UI/terminal HTTPS origins.
The existing safe reader renders only the terminal's `reading/1` projection.
`/material` retains credential omission and its original loopback configuration.
Neither credentials nor an authentication failure select the other profile.
The new route has no material or identity in its initial HTML. The runtime browser
uses isolated name resolution and container-local certificate trust; no host file
or machine-wide certificate store is changed.

`npm run test:access:reading` for real PostgreSQL 16, HTTPS and Chromium evidence.
The latter creates an owned, network-isolated container and two fresh synthetic
databases inside it. It uses actual invitation acceptance and password login before
the additive migration. No historical database or existing Docker volume is used.

The final local baseline passes 26 scenarios plus their parent (27/27), in 19.77
seconds excluding the container build. Eight new unit/configuration/boundary cases
pass, including an independent credential-profile mutation. R23 recorded 128 measured
requests per class after 12 warmups: medians 10.936 ms for absence and 10.996 ms for
NONE, Cliff delta -0.029, permutation p=0.707, no signal under the predeclared detector.
The +100 ms shifted control is detected. These observations do not prove universal
timing noninterference or a production latency bound.

The writer-free after-clock suspension returned 200 with original material received
after its deadline. `fullTemporalConformity` is **false**. R24 passing means the
experiment recorded and classified its result; the underlying temporal guarantee
failed in that run. No authentication/permission failure is excused by this limitation.

### Deliberate mutations

Each mutation below ran on a source copy inside its own container, not on the working
tree. All returned exit 1 with PostgreSQL and container cleanup. Counts include the
parent test, so one discriminating child failure normally produces two failed entries.
Elapsed times exclude image construction.

| Mutation | Observed failures | Result | Time |
|---|---|---|---|
| `drop-cursor-session` | R06: continuation from another session of the same account is wrongly accepted. | 25 passed / 2 failed | 18.00 s |
| `drop-reading-authority` | R10, R11, R12, R14 and R22: declarations, revocation or withdrawal no longer constrain material. | 21 passed / 6 failed | 18.29 s |
| `drop-reading-evidence` | R10, R13, R18, R20 and R26: required durable facts/commit observations are absent. | 21 passed / 6 failed | 17.25 s |
| `drop-reading-admission` | R14, R15 and R21: support, policy and session writers overtake the handoff. | 23 passed / 4 failed | 29.39 s |
| `drop-reading-generation` | R16: a mismatching generation no longer closes reading. | 25 passed / 2 failed | 18.19 s |
| `early-failure` | Explicit failure before scenario setup; cleanup still completes. | 0 passed / 1 failed | 4.59 s |

The pure reader-profile test also substitutes `omit` for the session request's
`include` and catches that change while preserving the old profile's independent
assertions. These mutations discriminate named properties; they are not an exhaustive
proof against future regressions.

## Retained limitations and follow-up

- ADR-035 awaits the owner's review. ADR-034 is not silently rewritten.
- Full writer-free temporal conformity, production data admission and external
  accreditation remain unimplemented/unaccredited.
- Organizational inputs, nominal names and scope policy are synthetic controlled
  fixtures. Public declaration/authority management and administration UI remain
  T05 or later admitted consumers. No master editor or generic grant endpoint exists.
- [BROWSER-I03 and BROWSER-J19](INC-02-T03.md#tracked-browser-follow-up) remain open.
  A passing run here does not diagnose either timeout. If either recurs, investigate
  the captured observations; do not label it environmental without evidence or
  increase waits/retries to obtain a green check.
- Early development checks found a missing Docker-context allowlist entry and an
  ambiguous browser selector matching both the navigation and form Sign in buttons.
  Both were corrected; their failed checks were not treated as passing evidence.
- A development mutation exposed a harness failure: without the expected policy
  deadline, the after-clock experiment could block for a session lifetime. Only its
  owned mutant container was stopped manually. The experiment now verifies the exact
  short deadline and caps the deliberate suspension at one second; per-scenario
  fixture restoration and gate cleanup also prevent failure cascades. The final six
  mutation runs above terminated and cleaned up without manual intervention.
- The first local original-browser launch found no bundled Playwright Chromium,
  before any assertion executed. The existing `READING_BROWSER_CHANNEL=chrome`
  option ran the browser and integration regressions successfully using installed
  Chrome. No browser installation or machine certificate change was required.
- The original contract, projector, source SQL, legacy identities, dependency
  versions and lockfile are preserved. No real mail, model call or paid service ran.
