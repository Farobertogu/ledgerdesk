# ADR-018 · Complete database schema and ledger contract

**Status:** accepted · **Decision date:** 2026-08-21

## Context

The specification's migration set did not apply on a clean database: three tables referenced by NOT NULL foreign keys had no DDL (`prompt_version`, `eval_split`, `kb_gap`), the `quality_report` schema was revoked and used but never created, and `ledger_entry` had row-level security enabled without policies. Separately, the ledger contract did not admit the row classes the design requires beyond agent calls — promotion attempts, modification events, commitment rows, the pre-registration anchor, calibration agreements — and had no start-of-run class and no anchoring of the chain head. A badly modelled ledger is lost, not migrated: this must be right before the first row is written.

## Decision

1. **Migration order, forward-only.** `0001_core.sql`: `create schema quality_report`; types `user_role`, `ticket_state`, `agent_kind`, `kb_gap_state`; the immutability trigger function; the seven core tables (`org`, `app_user`, `account`, `sla_policy`, `ticket`, `response`, `human_edit`) and the seven previously missing tables (`prompt_version`, `eval_split`, `eval_item`, `eval_result`, `kb_article`, `audit_event`, `kb_gap`); non-ledger RLS and grants. `0002_ledger.sql`: the `ledger_class` type and `ledger_entry` with its class contract; append-only triggers; ledger RLS, policies and grants; `ledger_checkpoint` with the same append-only locks; the two `kb_gap` → ledger foreign keys. `0003_kb_admission.sql` and `0004_eval_outcome.sql` as published. **`0004` must exist before the first sealed run; the data it holds cannot be produced afterwards.**
2. **Four database roles.** `app_rw` (application), `quality_ro` (pure reader), `quality_gen` (corpus generator: the declared writer of `eval_item`), `quality_eval` (evaluator: the declared writer of `eval_result`). The read-only test names exactly these two write exceptions and fails if a third appears.
3. **`ledger_class` has nine values**, in this order: `agent_call`, `start`, `promotion_attempt`, `modification_event`, `commitment`, `prereg_anchor`, `agreement_r3`, `kb_admission`, `checkpoint`. Each non-model class carries its own required payload keys or declared sentinel values; a free-form row is invalid by check constraint.
4. **Run accounting.** Every promotion **attempt** opens with a `start` row carrying its `attempt_id`, written when the attempt reserves budget and before its first generation — not the launch of a run; the invariant `starts == terminals` (promoted / rejected / aborted) is testable per attempt, and an aborted generation still consumes budget.
5. **Chain-head anchoring.** A `checkpoint` row every K content rows (K is the sealed sizing field of the same name), plus an external witness file `reports/ledger_anchor.log` committed to the repository; a closing row records the final row count. Rewriting repository history would destroy the witness, and is prohibited by process.
6. **Schema conformance test.** The migration test compares the applied clean-database state against the full published schema in both directions, with an exception list that starts empty; a sibling test asserts the migration set applies forward-only and deterministically.

## Consequences

The first code card (data spine) can be built and merged with this ADR as its authority; any later change to `migrations/` requires a new accepted ADR by the process gate. The ledger's shape is now fixed before any row exists — the alternative, migrating a mis-modelled ledger, was rejected as impossible by definition.

## Amendments — 2026-08-21

A review of the built data spine found six places where the published text, applied literally, does not deliver what it promises. Each line below supersedes the corresponding fragment of the decision above from this date; the decision itself is otherwise unchanged and stays accepted.

- **Row-level security on `ticket`, per-customer rule.** `customer_own_rows` is published as a permissive policy, and permissive policies are OR-ed: combined with `tenant_isolation` it left every customer able to read every ticket of their organisation, which is the opposite of the rule's own text. From today the policy is **RESTRICTIVE**, its predicate byte-identical. Supersedes the permissive form.
- **Row-level security on `response`.** `agent_writes` is published with a role predicate and no tenant predicate and no `with check`, and it was the table's only policy: any agent of any organisation could update any draft, and the table was unreadable for every role but the owner. From today the policy carries the tenant, reached through the ticket, in both `using` and `with check`, and a `response_tenant_select` policy gives the read path US-03 needs. Supersedes the published single-policy form. `human_edit` is declared to carry no row-level security in this migration; its policy lands with the console that writes it.
- **Grant of `eval_item` to the application role.** The published grant line gives `app_rw` `select` on `eval_item`, where every corpus body and every ground-truth label lives, and that table has no row-level security: the access is all or nothing. No published story reads it — the supervisor panel reads `eval_result`. From today the line is split and `app_rw` no longer reads `eval_item`. Supersedes the four-table grant to `app_rw`.
- **Sealed-manifest schema: `item_ids` uniqueness.** The published `$defs/split` allows duplicate ids, so a set could declare a cardinality that repetition covers, and the reconciliation compared lengths only. From today `item_ids` carries `uniqueItems`. Supersedes the unconstrained array.
- **Sealed-manifest schema: the emitting generator's own blocks.** The published root closes with `additionalProperties: false` while the generator emits `corpus`, `headroom` and `manifest_sha256`, so the emitted manifest could never validate and the sealing step would have had to strip the per-item clan fact to seal it. From today those three are declared properties — not required — so sealing adds `commitment` in place. Supersedes the root property list. `$defs/split` and `commitment` also close to additional properties, which is what keeps a label-carrying field out of a sealed set.
- **Mechanisms added in application of what this ADR already declares**, and named here so the migration set stays equal to the record in both directions: statement triggers that refuse `TRUNCATE` on the four append-only tables (a row trigger never fires on it and the revoke does not reach the owner); the chaining trigger and one-child index for `audit_event`, whose chain columns had no mechanism; `kb_gap_close_by_check()` with the trigger that refuses every other write of `kb_gap.state`; a monotone `seq` and a unique `(run_id, prev_hash)` index, without which the chain accepts a fork chosen by sequence number rather than by a forged hash; a declared refusal to chain outside READ COMMITTED; the cost sentinels, the hash shapes and the anchor's foreign key as check constraints instead of prose; a pinned `search_path` on every trigger function; and the two indexes the published per-ticket surfaces read through.
